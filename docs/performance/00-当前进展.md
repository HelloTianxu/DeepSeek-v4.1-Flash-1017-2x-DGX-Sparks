## 1. 当前目标与授权

| 项目 | 当前要求 |
|---|---|
| 主目标 | **双 DGX Spark，单流冷前缀 prefill ≥4000 输入 tokens/s** |
| 计时 | 主报 `实际未缓存输入token数 / server.prefill_seconds`；客户端TTFT口径并列，不混用 |

| 当前优先动作 | **①分离专家核心 2.00× 带宽缺口（重读 vs 内核低效）；②改 patch 加大 chunk 并单变量 A/B** |

历史3000/3500目标已被4000取代；decode的阶段目标不等于当前prefill目标。此前10–15分钟“只测基线”窗口已获批准并采用无重启短时探针完成部分诊断；随后用户给出空闲实验环境的更广授权，不能继续沿用“没有窗口批准”作为停工理由。

## 3. 当前基线与4000缺口

- 本轮自然技术文档冷前缀：约8K **1700–1739 tok/s**、约16K **1750–1780 tok/s**（不同实验请求，不是新统一中位数）。[原A/B数据](<../../runs/forge-20261123-interleave/prefill-summary.json>)。
- 用可复算的稳态head请求为预算锚点：N=8628，kernel窗口4.972653679s；对应约1735.09 tok/s。server prefill约4.977s，两口径不能混为精确同一值。[账面原始数据](<../../runs/forge-20261123-bottleneck-ledger/ledger.json>)。
- 新目标的**条件预算**：8628/4000=**2.157s**；相对该kernel窗口需减少**2.815653679s（56.62%）**。这不是4000正式验收，也不是严格物理不可达判决。
- 最大单项：专家核心约1.909s；其他GPU与通信工作、head空隙仍显著。具体拆分见[时间账](<01-发现与结论.md#2-时间账与4000条件>)。

## 5. 下一步，按判决价值而非调用栈长度排序

0. **已完成（本轮）**：硬件 roofline 分母实测。GB10 DRAM 读 **246.2 GB/s**、FP16 GEMM **100.82 TFLOPS**、
   平衡 **409.4 FLOP/byte**；专家核心 AI **204.4** ⇒ **带宽侧**，距带宽屋顶 **2.00×**。
   **算力不是绑定约束**；双 Spark 聚合带宽 492.4 GB/s 低于 Mac Studio 实测 707.9 GB/s。
   见 [E-ROOF-01](<../../runs/forge-20261123-roofline/REPORT.md>)。

1. **专家主战场（收窄后）**：只需分离 2.00× 缺口的两种解释——实际 DRAM 流量是否≈2×唯一字节。
   同一层、真实input/pick/权重原样replay，量 `dram__bytes` 与执行FLOP；不是普通BF16 GEMM替代品。
   **若已在屋顶，方向是消除 tile 重读；若不是，方向是内核效率。**
2. **端到端因果实验**：固定真实读取内容、ring和输出，只改变AIO提交批量。总时间降低才算收益；等待搬家不算。系统队列不先动。
3. **关键路径校准**：同一请求的GPU需求时刻、host层ready、两rank消息就绪与时钟误差对齐，确定Engram可回收量。
4. **加大 chunk（新增，条件投影≈2271 tok/s）**：`chunk_rows=2048` 为编译期常量，
   出厂 `tensorfold-native` 无 `TF_DS_PREFILL_CHUNK`，须改 `zig/patches/0008-pool-window.patch` 重编译。
   超过一分钟的构建先报时长并确认；A/B 须同时报 prefill、decode、正确性与激活/KV 峰值内存。

5. **组合前重测**：每个单项有效后再组合，重算木桶短板；同步报告prefill、decode/体验、正确性/质量及能耗，不按比例连乘。
