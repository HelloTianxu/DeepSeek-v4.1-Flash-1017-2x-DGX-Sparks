> ## ⛔ v1 → v2 方向性修订
>
> v1 认定「主因 = 反量化指令占据发射带宽」，据此把「减指令」列为主攻。**该结论已被判决实验推翻。**
> E-ALG-02 纯粹减 **17.41%** 指令（HMMA/ldmatrix/global读/warp% 全部 +0.00%），时间只 **−0.67%**，
> **弹性 0.038~0.058**；发射界余量 **3.38×**；stall 中等待类占 **60.15%**。
>
> **正确主因：内存延迟受限（latency-bound）+ warp 并发不足（33.20%，4 warp/scheduler）。**
>
> **路线变更**：
> - v1 路线 A「增大 R 64→128」**方向相反**（增 R 降并发，延迟受限下更可能变慢）⇒ 改为 **减小 R 64→32**
> - v1 路线 B「改解码算法减指令」**收益预期下调到接近零** ⇒ 降级
> - **新首选：提并发且保持流水线深度 S=3**
>
> v1 的全要素数据、DRAM 硬下界、验证方案、仿真器边界仍然有效。

## 一、系统性瓶颈：多点配平的数学形式

用户判断「单点优化拿到局部改进也不一定看到全局效果，因为存在多点配平」——**已被证实，并可写成精确形式**。

### 1.1 内核层：时间的三因子恒等式

```
T = N_inst × L_dep / (48 SM × 48 warp槽 × warp% × CLK)
```

三个因子由**同一组源码旋钮**控制，且方向相反：

| 旋钮 | 作用 | 代价 |
|---|---|---|
| `KB`（k-tile 步长）↓ | shared↓ ⇒ 可提并发 | **权重复用↓ ⇒ N_inst↑** |
| `S`（MMA_STAGES）↓ | shared↓ ⇒ 可提并发 | **权重复用↓ ⇒ N_inst↑**，且流水延迟隐藏↓ ⇒ L_dep↑ |
| `MINB`↑ | REG↓ ⇒ 并发↑ | **编译器重调度 ⇒ N_inst↑**（甩到 uniform/adu/cbu） |
| `MMA_ROWS`↑ | 权重复用↑ ⇒ N_inst↓ | shared↑、REG↑ ⇒ **并发↓** |

**实测四组，无一例外：并发每涨 ~50%，指令必涨 42%~89%。**

| 改动 | warp% | N_inst | 净时间 |
|---|---:|---:|---:|
| KB 4→2 | +0.03% | +35.08% | **+20.55%** |
| MINB 1→3（KB=2） | +49.70% | +42.03% | −6.18% |
| S 3→2 + KB=2 + MINB=3 | +49.94% | **+88.84%** | **+29.33%** |
| down red padding=4 | 不变 | 不变 | −1.08% |

**⇒ 参数层面已耗尽。这不是「还没调对」，是四个旋钮被同一组资源约束绑死。**

### 1.2 全局层：Amdahl 配平

当前口径 tok=10762、span=5157.783 ms、2086.56 tok/s。

| 部件 | ms | 份额 | 归因状态 |
|---|---:|---:|---|
| 专家核心（gate/up + down） | 2167.061 | 42.02% | 已判决 |
| 注意力 / HC | 906.308 | 17.57% | **从未归因** |
| 集合通信 | 642.315 | 12.45% | 已判决（达屋顶 92.2%） |
| 稠密 GEMM | 599.500 | 11.62% | 部分 |

| 其他 | 207.444 | 4.02% | **从未归因** |

**专家核心全归零也只到 3598.46 tok/s。4000 需削 47.84%，缺 300.222 ms ⇒ 单靠专家路径达不到 4000。**

**⇒ 全局要出明确变化，必须专家核心 + 注意力/HC 两处同时拿到正向收益。而注意力/HC 17.57% 至今从未归因，是最大的未知空白。**

### 1.3 两层配平的破解顺序（仿真给出）

| 单独改动 | 收益 | 绑定界 |
|---|---:|---|
| shared 流量归零 | −6.75% | issue |
| **DRAM 字节减半** | **+0.00%** | issue |
| 提并发（假设无指令代价） | −31.16% | issue |
| 更激进组合 | −36.35% | **dram** |

**当前绑定界是 issue（发射带宽），不是 dram。所以「减 DRAM 字节」这类优化现在收益为零；必须先把发射界压下去，减字节才开始兑现。**

**顺序：① 降 N_inst（解发行）→ ② 撞 DRAM 界后减字节 → ③ 全局再动注意力/HC。**

## 二、算法改进设计

### 2.1 全要素（已收集完毕）

**硬件**：48 SM × 4 scheduler × 48 warp槽，REG 65536/SM，shared optin 101376 B，GPC 2.273 GHz，DRAM 可持续读 246.2 GB/s，FP16 100.82 TFLOPS，L2 24 MiB。

**生产内核指令构成**（`raw/all-pipes.json`，总 1,756,808,496）：

| 管线 | 条数 | 占比 |
|---|---:|---:|
| alu | 717,729,264 | **40.85%** |
| fma | 561,994,416 | 31.99% |
| lsu | 211,271,184 | 12.03% |
| **tensor（HMMA）** | **98,242,560** | **5.59%** |
| fmalite | 92,026,337 | 5.24% |
| cbu | 39,641,328 | 2.26% |
| uniform | 13,062,816 | 0.74% |
| adu | 12,624,912 | 0.72% |

**SASS 静态直方图**（`grouped_mma_kernel<2,2,10,false,4>`）：
`LOP3 497 / MOV 482 / IMAD 476 / IDP.4A 288 / CS2R 287 / SHF.R 285 / IADD 188 / PRMT 172 / HMMA 144 / HFMA2 144`

**解码链路**（`decode.cuh`，生产 CB=2 `CB_MUL1`、K2=6 即 3 bits/value）：
每 2 个值 = `2×IMAD(s*0x83DCD12D) + 2×IDP4A(字节和) + 1×PRMT(打包) + 1×HFMA2(scale)`；
加上 `lane_states` 的 8 次 `window16`（SHF+LOP3）。
**⇒ 解码 : 数学 ≈ 6 : 1，与实测 ALU:HMMA = 7.31:1 独立吻合。**

**硬下界**：DRAM 1.861 GiB / 246.2 GB/s = **8.1181 ms**，当前 12.7547 ms ⇒ **最多 1.571×**。

### 2.2 已否决的改动（勿重试）

| 候选 | 判决依据 |
|---|---|
| KB / S / MINB 任意组合提并发 | 四组实测，指令增幅吃掉并发收益（§1.1） |
| KB=4 下凑 3 blocks | padding 不能动（ldmatrix bank）、S 不能降、bsh 单缓冲仍超 2304 B ⇒ **无实现路径** |
| `(h0&0xffff)\|(h1<<16)` → `__byte_perm` | **两版 SASS 完全相同，nvcc 已自动优化**（E-ALG-01 预筛否决） |
| 「反量化打满 ALU」 | 所有数学管线 ≤33.55%，无一饱和 |
| spill 是拦路石 | spill 指令仅占增量 **1.28%**，真身是 uniform/adu/cbu 重调度 |

### 2.3 三条候选路线（按证据强度排序）

#### ~~路线 A：增大权重复用行数 R（64 → 128）~~ ⛔ **v2 已废：方向相反**

延迟受限下增大 R 会降低并发，得不偿失。**正确方向是减小 R 到 32**，见下方新路线 A′。

#### 路线 A′（v2 新首选）：减小 R 64→32 + MINB=3 —— 提并发但保持 S=3

**依据**：指令弹性仅 0.058 ⇒ 用指令换并发划算，前提是不削弱流水线深度。
`MMA_ROWS 64→32` 使 shared 44288→31360 而 **S=3 不变**，是唯一满足该前提的候选。

**编译期预筛已过**：R32+MINB3 ⇒ REG 80 / spill 24B / shared 31360 ⇒ **blocks min(3,3)=3**。
（R32+MINB1 无效：REG 仍 124 ⇒ reg 限死 2 blocks。）

**阻塞**：运行期 `illegal memory access`。`MMA_ROWS` 与 warp/ldmatrix 行布局、work 列表编码强耦合
（8 warps 按 `dk=(warp>>2)*MMA_DEC_, dn=warp&3` 分 2×4；64 行 = 4 个 m16 tile；`:710` grid.z 走 64-row block）。
**需源码级适配行映射、work 编码、epilogue —— 属重写施工，非参数调整。**

#### ~~路线 A（原文保留）~~：增大权重复用行数 R（64 → 128）

源码 `experts_grouped.cuh:890` 明写：**「R member rows a program: 128 decodes a weight tile half as often as 64」**。
当前每专家平均 224 行（14336×6/384），R=64 ⇒ 同一权重解码 3.5 次；R=128 ⇒ 1.75 次 ⇒ **解码指令减半**。

**这是唯一能直接砍 N_inst 而不靠编译器重调度的杠杆。**

**阻塞**：`mma2` 内核要求 `N % 256 == 0`，生产 N=1152 不满足（1152 = 256×4.5）。
**改动内容**：把 `M2_COLS` 256 → 128，使 N=1152 可整除；同步核对 `m2_rows_bytes()`、work 生成、Z 布局。
**代价**：R=128 使 `As_s` 翻倍 ⇒ shared↑ ⇒ 并发↓，**需实测净效应，不得连乘推算**。
**已知风险**：mma2 与 v1 **非位一致**（rel 7.119e-06），需先定性该误差是否可接受。

#### 路线 B：降低 trellis 解码指令数 — ⛔ **v2 降级：弹性 0.058，收益预期接近零**

当前 3 bits/value 用 16-bit 窗口 + 魔数乘 + 字节和（`IMAD + IDP4A`）实现，每值约 6.4 条标量指令。
若改用**直接位索引 + 小表查值**（3 bits ⇒ 8 项码本），指令数可数倍下降。

**代价**：**改变数值语义，非位一致**，且需重新量化权重或证明等价。
**前置**：用户需明确「是否接受非位一致」「是否接受换量化格式」——**此授权边界至今未确认**。

#### 路线 C：注意力 / HC 归因（17.57%，906.308 ms）— **全局收益的必要条件**

从未归因。`_hc_mix_pf` 728.40ms/n602、`_sparse_attn_part` 669.95ms/n320、`rot_in_kernel` 588.28ms/n2188、`_hc_finish` 224.19ms/n653。
**在专家核心之外，这是唯一有量级可挖的空白**，且 4000 tok/s 缺的 300.222 ms 只能从这里补。

**改动内容**：先归因（ncu 分管线 + 恒等式三因子），再定优化。**未归因前不得立项优化**（手册 §7.19 硬规矩）。

### 2.4 验证方案（每条路线统一）

1. **编译期预筛**：`cuobjdump -res-usage` 读 REG / spill / shared，算 blocks；`-sass` 静态直方图对比解码指令条数。**不通过则不进入实测。**
2. **干净性判据**（新增 §7.24）：改分块参数时 **HMMA / ldmatrix / global 读条数必须完全不变**；改解码算法时 HMMA 不变但 ALU 应变。
3. **同场 A/B**：对照臂同场重测，A/B/A/B 交替 ≥12 轮，臂间 0.25s 冷却，看配对差是否同向。
4. **机制闸**：`-k regex:<内核名>` 过滤（**不加 -k 会抓到小 kernel**），验到目标机制量本身。
5. **数值闸**：`torch.equal` 位一致；非位一致须给出 rel 误差并由用户裁定。
6. **端到端**：`tools/probes/cold_prompt.py` 同形状口径，与 2084.42 tok/s 基线比。

## 三、测试与仿真模型

`tools/sim-kernel.py`（Mock 硬件，纯本地无 GPU），三子命令 `explain | calibrate | scan`。

**模型**：发射界 + 资源界（shared / DRAM / tensor）+ 依赖延迟 `L = L0 + Σ s_k·u_k` 迭代求解。
**标定**：`s_shared = 2.2717`（down PAD 实验）；S0 精确复现，S1/S2 自校验误差 ~7%。

**能力边界（E-SIM-02 暴露，必须遵守）**：

- ✅ 给定 `N_inst / warp% / L_dep` 三因子 → 算时间（误差 1~3%）
- ✅ 算资源硬下界（DRAM 8.1181 ms）
- ✅ 判断当前绑定界、给出破解顺序
- ❌ **不能预测「源码改动 → 指令数」**。S3 预测 −18.12%，实测 **+29.33%**，因为模型假设「无 spill 即无指令代价」，而真实代价来自编译器把 work 甩到 uniform/adu/cbu。

**⇒ 纪律：仿真只用于筛选方向与算上界，收益一律实测锁定。凡涉及 REG 压力或循环结构的改动，模型无预测能力。**
