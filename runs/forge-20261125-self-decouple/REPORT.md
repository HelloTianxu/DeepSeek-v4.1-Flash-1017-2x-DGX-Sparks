## §1 重大方法更正：sink 链被死代码消除，`asm volatile` 一起被删

### 1.1 事实

为把 MODE 3 的失真修掉，本轮新增 **MODE 8 = 只摘 MMA，让 4 个 `a[]` 与 8 个 `bb[]` 全部保持活跃**，
判据是 `LDSM` 必须等于 MODE 0 的 76,677,120。实测：

| 臂 | LDSM | shared_ld | 总指令 | REG | SASS(LDSM/HMMA/LDS/LOP3) |
|---|---:|---:|---:|---:|---|
| MODE 0 完整 | **76,677,120** | 84,965,832 | 2,758,024,926 | 133 | 16 / 64 / 154 / 199 |
| MODE 8 只摘MMA(sink) | **0** | 84,965,832 | 2,648,793,150 | 56 | **0 / 0** / 154 / 261 |
| MODE 9 完整+栅栏 | 76,677,120 | 84,965,832 | 2,758,024,926 | 133 | 16 / 64 / 154 / 199 |
| MODE 10 摘MMA(进真实acc) | **49,121,280** | 84,965,832 | 2,862,025,758 | 64 | — |

MODE 8 的 `LDS` 与 MODE 0 **逐个相等（154）**，`LDSM` 直接归零
⇒ ldmatrix **不是被替换成普通 shared 读，是整条被删除**。

### 1.2 根因（源码 + SASS 双向定位）

`ldmatrix_x4`（原件 `:580-585`）是 **`asm volatile`**，编译器不可能把它「降级」。真实机制是：

1. `m2_slice` 的 sink 兜底只写 `acc[0][0][0] = 1.f`（工作副本 `:933`）；
2. MODE 8 下没有任何 MMA 写 `acc`，编译器把 64 个累加寄存器**折成常量**，
   落盘处（调用方 `:1021/:1023`）只需一个 select ⇒ REG 133→56；
3. 于是 `m2_sink` 被判为不影响任何真实输出 ⇒ 8 个操作数全死；
4. **nvcc 在输出全死时连 `asm volatile` 一并删除**（与 GCC 的 `volatile` 语义不同）。

### 1.3 波及范围（对既有结论的更正）

**MODE 1 / 3 / 6 / 8 四个臂全部建立在同一个失效的 sink 上。** 因此：

- **更正 E-SELF-09 §关于 MODE 3 的解释**：原文「`ldsm=0` 是编译器把只用 `a[0]` 的 ldmatrix
  降级成普通 shared 读」**错误**。真因是 sink 链死代码消除，`asm volatile` 被删。
- **更正 E-SELF-10 §2 的 2×2 析因**：四格中
  MODE 0（算术Y同步Y）与 MODE 5（算术Y同步N）的 `acc` 活跃、**保真**；
  MODE 3（算术N同步Y）与 MODE 6（算术N同步N）**同时少了 ldmatrix 与 `ts[]` 读流量**。
  ⇒ **「算术」这个因子捆绑了「shared 读流量」，该 2×2 不是干净的 2×2**，
  超加性 2.74× 不能全部归给「算术 × 同步」的交互。
  原表数值保留，此批注为其口径限制。
- **仍然成立的部分**：MODE 4/5 只摘同步、`acc` 活跃 ⇒ **「同步依赖的代价 ≈3.8%」保真有效**。

### 1.4 三次尝试三种失真 ⇒ 摘部件法在此内核上不可用于构造「无算术」臂

| 尝试 | 设计 | 失真 |
|---|---|---|
| MODE 3（历史） | sink 兜底 | LDSM=0，`ts[]` 读也死 |
| MODE 8（本轮） | 4 个 a + 8 个 bb 全进 sink | 同上，LDSM=0 |
| MODE 10（本轮） | 操作数归约进**真实** acc | LDSM 只剩 **41/64**（`if(i<live)` 由谓词化改真分支，均值 live=41/16=2.5625）；整数指令 **+104M(+3.8%)** |

**但上界仍可用**：MODE 8 与 MODE 10 的失真方向**相反**（前者少 shared 读、后者多整数 ALU），
两者给出**同向的小效应**：

| 臂 | min-of-min | 同场 MODE 0 | 配对差 |
|---|---:|---:|---:|
| MODE 8 | 22.1714 | 22.7505 | **−2.54%** |
| MODE 10 | 22.5085 | 22.7211 | **−0.94%** |

⇒ **「摘掉整个 tensor 管线的收益 ≲2.5%」这个上界是稳的**，不依赖任一臂的保真度。
**tensor 管线不是杠杆。**

## §2 闸 B：反向同步定价（唯一完全保真的新臂）

**MODE 9 = 完整算术 + 每 stage 计算后多一次 `__syncthreads()`**，语义不变。

- **正确性闸：`torch.equal` = True，maxdiff = 0**（必须位一致，已过）
- REG 133、LDSM 76,677,120、总指令 2,758,024,926 **与 MODE 0 逐项相等**；SASS 仅 `BAR` 3→4
- 时长 **22.7236** vs 同场 MODE 0 **22.7505** ⇒ **−0.12%，噪声内**
- 规模：NS = KT/KB = 320/4 = **80 stage/程序**，7488 程序 ⇒ 额外 **599,040 次 block 栅栏**，墙钟不动
- stall 归一后 barrier 19.2%→19.6%，其余各项几乎不动

**结论：block 栅栏的 rendezvous 指令成本≈0。MODE 0 里 19.2% 的 barrier stall 不是栅栏本身的开销，
而是 warp 在等最慢的那个 warp，后者在等数据。**

这用**语义正确**的臂复证了 E-SELF-09e 用竞态探针得到的「栅栏只是依赖显现处」，
并直接回答用户风险 3：**specialization 的反向同步在「指令成本」这一侧是便宜的；
真正躲不掉的是依赖本身**（`load(st+S-1)` 写的 slot 是 `(st-1)%S`，加一个 slot 也无用，
`st+S ≡ st-1 (mod S+1)`，追圈距离永远落在刚被消费的那格）。

## §4 288 线程 occupancy 重算（更正我原先的说法）

我原先说「65536/288 = 227 > 133 所以够」——**这个论证是错的**，它把每线程上限当成了 block 数判据。
按实测 REG=133（cuobjdump 粒度对齐后 **136**）重算：

| 线程数 | 每线程寄存器上限 | 寄存器限 blocks | shared 限 blocks(S4/KB4=61440) | 实际 blocks | warps/SM | 占用率 |
|---:|---:|---:|---:|---:|---:|---:|
| 256 | 256 | **1**（2 block 需 69632 > 65536） | 1 | **1** | 8 | 16.67% |
| 288 | **227（对齐 224）** | **1** | 1 | **1** | 9 | 18.75% |

- ncu 实测 MODE 0：`launch__occupancy_limit_registers=1`、`launch__occupancy_limit_shared_mem=1`、
  `warps_active=16.7%` ⇒ **寄存器与 shared 双双把 block 钉在 1**。
- **256→288 不改变 blocks/SM**，只是 8→9 warp，**consumer 仍 8 个、MMA 吞吐不变**。
- 真正的风险是**每线程寄存器上限 256→224**：specialization 新增活跃状态（mbarrier、producer 指针、
  自旋计数）会挤这 224 的额度 ⇒ **必须编译期预筛 spill，只让 STACK:0 LOCAL:0 的变体上机**。

## §7 前置检查导出的下一步（唯一未被混淆的占用率检验）

复核 E-SELF-09 的「MINB=2 真拿到 2 blocks/SM 却更慢」时发现**该否决存在混淆**：

- S=4 / KB=4 的 shared = **61440**，2 block 需 122880 > optin 上限 **101376** ⇒ **拿不到 2 block**；
- 因此当时读到「占用率 15.55→35.38%」的那个臂只能是 **S=3, MINB=2**（46080×2 = 92160 ✓）；
- 而 **S=3 本身就有 −1.3% 的负收益** ⇒ 「2 blocks 更慢」与「S=3 更慢」混在一起，归因不成立。

**从未测过的组合：S=4 + KB=2 + MINB≥2。** shared = **32768** ⇒ 可容 **3 blocks/SM**，
即 **24 warps/SM、占用率 50%**，且**保持满深度 S=4**。这是唯一能在不牺牲深度的前提下
把独立 warp 数翻 2–3 倍的干预，直接针对「每 stage 串行依赖 + 8 warp 填不满空隙」这个结构。

工程前提：现有 dispatch 的 `pm==0 && pk==2` 分支**排在 MINB 分支之前并直接 return**，
无法组合 ⇒ 需新增一条 `pk==2 && pb>=2` 分支，并逐臂用 mangled 名断言 + 编译期 spill 预筛。

**战略落点不变**：mma2 即使做成也上不了生产（`N%256` 挡住 TP2 本地 N=1152、与 v1 非位一致）；
**down3 能跑生产形状 N=5120 且同为 cp.async 环结构** ⇒ mma2 做原型、验证后移植 down3
（down 占 12.59%，−15% 约 +2.0% 全局）。

## §8 本轮自纠与工程纪律（新增）

1. **`asm volatile` 在 nvcc 下输出全死时会被删除**，与 GCC 语义不同。
   ⇒ **「摘部件」探针的兜底必须写进真实输出（acc/全局内存），不能用只喂一个条件常量的 sink。**
   验收判据必须是**指令计数器逐项相等**（LDSM / shared_ld / 总指令），不是「我觉得操作数还活着」。
2. **谓词化 vs 真分支会随数据flow改变**：MODE 10 的 `if(i<live)` 从谓词化变成真分支，
   LDSM 掉到 41/64。**同一个 `if` 在不同 MODE 下发射行为不同**，跨 MODE 比指令数前先核这一项。
3. **失真方向相反的两个臂可以夹逼出可信上界**，即使两个臂都不保真。
   本轮 tensor 管线 ≲2.5% 就是这样得到的。
4. **「MIO 不爆」是必要条件不是充分条件**。凡「若 X 不爆则上 Y」的判据，
   必须**另算 Y 的收益上界**，否则会把「没被否决」当成「值得投」。
5. **`grep | head` 在 `set -euo pipefail` 下会静默掐断整个循环**：head 提前关管道给 grep SIGPIPE，
   而外层再套 `| tail` 会把退出码掩盖成 0。本轮因此只跑了三臂中的第一臂。
   ⇒ 改用 `sort -u` 等读尽输入的算子，或 `|| true`。
6. **GB10 的 `smsp__average_warp_latency_issue_stalled_*.pct` 返回原始量级**（单位标 `%` 但值是周期），
   必须按各 reason 合计归一，否则会把 4,303,133 当成百分比。
7. **`cuobjdump -res-usage` 用 `grep -A4` 会串到下一个函数的资源**，必须按 `Function` 块切分后逐块取。
8. **scp 多个远程路径写在同一个引号参数里会被当成单个路径**，用 `ssh … tar cf - … | tar xf -`。
