# E-RECLEAN-01：口径重采 + 三个核心问题的判决

用户指令：**「先把数据理清。然后回归内核不饱和这个主战场」**，并给出三个核心问题：
① 硬件是不是真的受限？② 若没受限就是软件问题？③ 全栈是否开源、有无闭源阻塞我们开发？
**「如果没有，那是一个可以触达的软件问题，就按软件问题来解，不行全部重写。」**

## §0 判决表

| 问题 | 判决 | 依据 |
|---|---|---|
| **① 硬件真的受限了吗** | **没有。没有任何一项物理资源饱和** | 专家内核发射 27.28%、SM 49.21%、Tensor 50.0%、L2 24.31%、L1TEX 21.0%、warps 16.7%、mio_throttle **0.9%** |
| **② 是软件问题吗** | **是。且已定位到具体浪费项** | **6.356 GiB 访存中 2.928 GiB（46%）是激活被 9 个列块各重复 staging** |
| **③ 有闭源阻塞吗** | **没有。主战场 52.26% 的源码完全可触达，且已实证重编位一致** | `exl3-source-gate.sh` 从公开源码重编 `experts_cb2.cu`，SASS 与 kit cubin 比对通过 |
| **④ 常规流水线手段还有空间吗** | **基本封闭** | 加深 S、摘栅栏、warp specialization 三条全部实测否决（上界 ≲0.5%–2.5%） |
| **⑤ 那还剩什么杠杆** | **减少访存量本身（算法/布局层），不是流水线调参** | 46% 重复 staging 是唯一未被否决的大项 |

**并发现一处文档内部矛盾（本轮更正）**：E-SELF-10 §④ 称「减列块收益上界被计算侧 3.46 ms 封顶」，
但 E-SELF-11 §⑤ 用**反向夹逼**证明「摘掉整个 tensor 管线 ≲2.5%」⇒ **计算侧不是止点，那条封顶失效**。
减访存量的收益上界须重新评估，**不能沿用 E-SELF-10 的封顶结论**。

## §2 问题①：硬件没有受限——「同时不饱和」是配平的必然表现

**关键：E-SELF 系列的利用率读数不受本次口径污染影响。** 它们是**离线单内核回放**，
固定真实形状（r=2048、slots=7、p=14336、d=5120、i=1152 TP2 本地、k2=6），
**不读 engram、与请求 token 数无关** ⇒ 仍然有效。

E-SELF-11 §⑥ 全局达成率（专家内核）：

| 资源 | 达成率 |
|---|---:|
| 发射 `smsp__issue_active` | **27.28%** |
| SM | 49.21% |
| Tensor Pipe | 50.0% |
| **L2** | **24.31%** |
| L1TEX | 21.0% |
| warps（占用率） | 16.7% |
| **mio_throttle** | **0.9%** |

stall 归一：math_pipe_throttle 22.6 / wait 21.6 / barrier 19.2 / selected 14.2 / long_scoreboard 10.2 / mio_throttle 0.9。

**⇒ 没有任何一项接近饱和，连片内路径（L2 24%、L1TEX 21%）都远未打满。**

**这不是「延迟受限」这种同义反复，而是有具体结构的判决**（E-SELF-10 §④）：
> 配平流水线里内存侧与计算侧**互为止点**，谁也不能跑到前面 ⇒ 同时不饱和是**配平的必然表现**。

**要吃满一侧，必须打破配平，即改变「每搬运字节的算术量」。**

**已封闭的常规手段（勿重试）**：
- 加深流水 S∈{3,4,5,6}：S=4 恒最优，其余 ±1.8% 内（E-SELF-09/11 双向复证）
- 摘 block 栅栏：MODE 9 语义正确、位一致，额外 599,040 次栅栏 **−0.12%（噪声内）** ⇒ rendezvous 免费
- warp specialization：`ldgsts` 占总指令 **0.483%**、发射仅 27.28% ⇒ 发射解耦上界 **≈0.5%**
- 提占用率：REG 255 钉住 16.7%，两个低寄存器变体抬到 25% 却都掉吞吐（−0.92%/−2.38%）
- 288 线程：不改 blocks/SM，consumer 仍 8 个、MMA 吞吐不变，且每线程寄存器额度 256→224 有 spill 风险

## §3 问题②：是软件问题，且浪费项已定位到字节

**E-SELF-10 §④ 原文**：
> 最大可动项：**6.356 GiB 中 2.928 GiB（46%）是激活被 9 个列块各重复 staging**。

**这是明确的、可量化的软件浪费**——不是硬件的物理限制。

同场屋顶标定 **15.9018 ms / 429.2 GB/s（6.356 GiB）**（纯搬运、不算术）。
生产基线臂 22.7459 ms ⇒ **相对同场屋顶 1.43×**。

### 3.1 本轮更正：E-SELF-10 给收益设的「计算侧封顶」失效

| 出处 | 论断 | 状态 |
|---|---|---|
| E-SELF-10 §② | 算术/同步联合 4.304 ms（62.9%），staging 2.541 ms（37.1%） | **2×2 不干净**（sink 只写 `acc[0][0][0]`，nvcc 连 `asm volatile` 一起删；MODE 1/3/6/8 四臂同缺陷，E-SELF-11 已查明） |
| E-SELF-10 §④ | 减列块「收益上界被计算侧 **3.46 ms** 封顶」 | **失效** |
| E-SELF-11 §⑤ | **反向夹逼**：MODE 8（LDSM=0）−2.54%、MODE 10（多 104M 整数指令）−0.94%，**失真方向相反而效应同向** ⇒ 「摘掉整个 tensor 管线收益 **≲2.5%**」，**该上界不依赖任一臂保真度** | **有效，采信** |

**⇒ tensor 管线不是止点。减访存量的收益不再被 3.46 ms 封顶，上界须重新评估。**

### 3.2 收益上界（Amdahl，禁止连乘）

以**专家核心达到同场纯搬运屋顶**为保守锚点：
22.7459 → 15.9018 ms = **−30.1%**，专家核心份额 42.02%
⇒ 全局上界 **42.02% × 30.1% ≈ 12.6%**，prefill 2084 → **约 2350 tok/s**。

**这只是保守锚点，不是预测**：若 46% 重复 staging 真被消除，**屋顶本身也会下降**（搬的字节少了），
上界会更大；但**禁止按字节比例连乘**（手册 §7 硬规矩），且必须实测。
**真实收益必须用同场 A/B 配对验证，不得用本估算代替。**

### 4.2 结论

**主战场（专家路径 52.26%）源码完全可触达，且我方已跑通「改源码 → 编译 → SASS 位一致校验 → 替换 cubin」全链路**
