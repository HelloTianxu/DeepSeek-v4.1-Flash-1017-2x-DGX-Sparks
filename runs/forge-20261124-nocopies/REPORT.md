# E-ABS-02 · `TF_DS_NO_COPIES` 判决：**否决**

**性质**：我方基线自有开关（非社区增量），从未 A/B 过，本轮补验。
**结论**：**不得设为默认。** 常规探针 +0.3~0.6%，但重复文本场景单流 **−4.7%**。
先前的「正收益」是**探针选择偏差**。

---

## 1. 机制（读代码）

`zig/src/core/lanes/windows.zig:136`
```zig
if (!copyAllowed(e.cfg.copy_proposals, e.cfg.max_copy, s.force.items.len)) return &.{};
```
`TF_DS_NO_COPIES=1` → `copy_proposals=false` → **suffix-lookup 复制窗口整体关闭**，
改由 draft head 提议。代码注释：*"the Python engine makes no copies either"*。

复制窗口的作用：当生成文本重复了上文已出现的内容时，直接复制后缀而不必逐 token 起草。
**因此它的收益与「生成内容对上文重复程度」强相关。**

---

## 2. 场景一：常规探针（47 token 短 prompt → 生成 512 token）

交替 A/B/A/B，同场、同一二进制（alias 已开的新地板），仅 env 不同。

| | A1 | B1 | A2 | B2 | 配对差 |
|---|---:|---:|---:|---:|---:|
| N=1 | 59.087 | 59.267 | 59.142 | 59.350 | +0.30% / +0.35% |
| N=4 聚合 | 107.251 | 108.048 | 107.406 | 107.822 | +0.74% / +0.39% |

- 四次配对**全部同向为正**；同配置内散布 0.09–0.21%，效应为其 2–3 倍。
- **N=1 的 tok/轮 四次恒为 2.0157**，涨的是轮/秒 → 去掉复制窗口省开销、未丢 token。

**表面结论：小而真实的正收益。**

---

## 3. 场景二：对抗探针（长重复文本 + 要求逐字复述两遍）

构造：5351 字符的重复段落，指令要求 verbatim 复述 → 复制窗口充分发挥。
同样交替 A/B/A/B。

| | RA（copies ON） | RB（OFF） | RA2（ON） | RB2（OFF） | 配对差 |
|---|---:|---:|---:|---:|---:|
| **N=1** | **85.570** | **81.402** | **85.280** | **81.477** | **−4.87% / −4.46%** |
| N=1 tok/轮 | 3.5068 | 3.3247 | 3.5068 | 3.3247 | **−5.2%** |
| N=4 聚合 | 107.239 | 107.966 | 107.428 | 107.738 | +0.68% / +0.29% |

**机制清楚**：重复文本下 tok/轮 达 **3.5068**（常规场景仅 2.0157），
说明复制窗口**在实打实产 token**；关掉即掉到 3.3247，吞吐随之下降。

N=4 仍微正，是因为四路摊薄轮预算后复制贡献变小（tok/轮 ≈1.90，两臂接近）。

---

## 4. 判决

**否决，保持默认 off（即复制窗口开启）。**

理由：
1. 用户头条指标是**单流**，而单流在重复场景亏 **4.7%**，远大于常规场景赚的 0.3%。
2. 真实 agent 负载充满重复：工具输出回放、文件内容引用、代码编辑、多轮 reasoning 重放。
   **对抗场景才是代表性场景，常规短探针是乐观偏差。**
3. 收益方向随负载翻转的开关，不适合做全局默认。

**保留价值**：若将来出现「确定低重复、且以多流聚合吞吐为目标」的专用负载，
可作为一个 opt-in 调优项，但需该负载自己的 A/B 支撑。

---

## 5. 方法论教训（已写入开发手册）

**探针选择偏差**：一个开关在合成探针上为正，不等于它在真实负载上为正。
凡是**改动投机/复制/草稿机制**的开关，必须补一个**对抗性负载**（最大化该机制贡献的场景）再判决。
本轮若只看场景一，就会把 −4.7% 的真实退化当作 +0.6% 的收益锁进基线。
