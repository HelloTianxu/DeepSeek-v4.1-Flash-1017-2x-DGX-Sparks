# E-OCC-02 / E-OCC-03：根因 100% 定死 —— MLP 不足，DRAM 带宽只发挥 61.1%

2026-11-25 ｜ gate/up `grouped_mma_kernel` ｜ 生产未停服、`start.sh` 未改动
数据 `raw/`：`occ-b{2,1}.csv`、`o3-b{3,2,1}.csv`、`dyn-ab.json`、`dyn3-ab.json`、`bandwidth.json`、`final-verdict.json`

## §0 归因（定案）

**主因：warp 并发不足 → 内存级并行（MLP）不足 → DRAM 有效带宽只发挥屋顶的 61.1% → 内核时间被拉长 1.633 倍。**

不是指令数、不是 bank 冲突、不是 spill、不是栅栏开销、不是时钟、不是 ALU 吞吐。

**生产工作点**：有效带宽 **150.49 GB/s** / 标定可持续读 **246.2 GB/s** = **61.1%**。
DRAM 流量 1.862 GiB 固定 ⇒ 理论下界 **8.1352 ms**，当前 ncu 口径 13.2854 ms ⇒ **余量 1.633×**。

## §1 判决实验：纯净 occupancy 探针（位一致，非机制探针）

**方法**：KB=4 时模板常量 `DYN=false`，kernel 使用静态 shared 数组，
`extern __shared__ mma_dyn[]` **完全不被访问**。因此启动时多申请动态 shared
只压低 blocks/SM，**不改一条指令、不改一个输出位**。

两臂**共用同一模块**，仅切环境变量 `TF_MMA_DYN_PAD` ⇒ 无模块间差异，是最干净的单因素 A/B。

| 配置 | 静态+动态 shared | blocks/SM |
|---|---:|---|
| pad=0（生产） | 44288 | 2 |
| pad=20000 | 64288 | 1 |

**实测（12 轮 A/B 交替，臂间 0.25s 冷却）**：
`blocks2 12.6506 ms → blocks1 16.4460 ms`，**+30.00%**，
**位一致 `torch.equal=True` maxdiff=0**，配对差 6/6 同向，逐对 [29.60, 29.98, 29.98, 30.15, 30.17, 29.85]，极差 0.57pp。

**机制闸确认干预纯净**：

| 量 | blocks2 | blocks1 | 变化 |
|---|---:|---:|---:|
| **总指令** | 1,756,808,496 | 1,756,808,496 | **+0.00%** |
| DRAM sector | 62,478,748 | 62,527,354 | +0.08% |
| L2 读 sector | 304,415,349 | 304,519,787 | +0.03% |
| **L2 命中率** | **79.49%** | **79.47%** | −0.02pp |
| warp% | 33.19 | 16.57 | −50.08% |
| **有效 DRAM 带宽** | **150.49 GB/s** | **108.72 GB/s** | **−27.76%** |
| 达屋顶 | **61.1%** | 44.2% | |

## §2 三点扫描否证了简单分解，却给出真正的机制

KB=2+MINB=3 模块（shared 23808 / REG 80）可用 pad 做出 **3/2/1 blocks 三档**，
**三档指令完全相同（3,370,408,128）**，全部位一致。

| blocks | warp% | T(ms) | 有效带宽 | 达屋顶 |
|---|---:|---:|---:|---:|
| 3 | 49.71 | 15.0392 | 133.18 GB/s | 54.1% |
| 2 | 33.19 | 17.4627 | 114.46 GB/s | 46.5% |
| 1 | 16.63 | 28.0070 | 71.44 GB/s | 29.0% |

**先否证一个中间假设**：E-OCC-02 两点拟合 `T = A/warp + B` 得 B≈8.855 ms，
曾推测 B 是「不可掩盖的 DRAM 传输基座」。**三点证明该模型不成立**：
1/blocks 坐标下斜率从 10.19 跳到 20.72（翻倍），B 在两组间也不一致（8.86 vs 5.68）。
**两点拟合必然完美，不足以立论 —— 该推断已作废。**

**真正的规律是 `T = DRAM字节 / 有效带宽`，而有效带宽是并发的函数：**

| 对照（指令完全相同） | 时间比 | 带宽比倒数 | 误差 |
|---|---:|---:|---:|
| KB2 3→2 blocks | 1.1611 | 1.1635 | **−0.20%** |
| KB2 3→1 blocks | 1.8623 | 1.8643 | **−0.11%** |
| KB4 2→1 blocks | 1.3853 | 1.3842 | **+0.08%** |

**五个独立对照，误差全部 ≤0.2%。时间完全由有效 DRAM 带宽决定。**

**另一发现**：同为 warp 33.19%，KB=4 带宽 150.49 而 KB=2 只有 114.46 GB/s。
**KB 越大，每步预取字节越多，MLP 越好** —— 这解释了 KB 4→2 为何变慢（不是「指令 +35%」）。

## §3 为什么这次是 100%，而前几轮不是

| 轮次 | 结论 | 证据缺陷 |
|---|---|---|
| E-SIM-01/02 | 「指令占据发射带宽」 | 只有「增指令⇒变慢」单向数据，改动同时动了流水线/重调度；恒等式是代数式非因果 |
| E-ALG-02 | 「延迟受限+并发不足」 | 减指令侧干净，但**提并发侧无对等纯净证据**；且与 E-OCC-01 的 −6.18% 存在解释矛盾 |
| **E-OCC-02/03** | **「MLP 不足 ⇒ 带宽 61.1%」** | **无缺陷**：纯净探针位一致、指令/字节/L2命中全不变、五对照 T∝1/BW 误差≤0.2%、带宽随并发单调且跨两组 KB 成立 |

**关键差别：这次直接测到了中介变量（有效带宽），并证明 T 与它一一对应。**
前几轮都停在「相关」，这次是「机制链闭合」。

### 内部矛盾已解决

E-OCC-01 `KB=2 MINB 1→3`（2→3 blocks）实测 −6.18%，而纯净 3→2 是 +11.85%（反向 ≈ −10.6%）。
差额 `0.9382/0.8940 = 1.0494` ⇒ **指令 +42% 的净代价仅 +4.94%，弹性 0.118**，
与 E-ALG-02 的 0.038 同量级（均 ≪1）。**两处解释现已自洽。**

## §4 改进目标（唯一方向：提 MLP）

**目标量化**：把有效带宽从 150.49 GB/s 推向 246.2 GB/s。

| 情形 | gate/up 倍率 | 全局 tok/s | vs 2086.56 |
|---|---:|---:|---:|
| blocks 2→3，带宽~75%（保守） | 1.227× | 2202.4 | +5.55% |
| blocks 2→3，带宽~85%（乐观） | 1.391× | 2267.8 | +8.69% |
| 达屋顶 100% | **1.633×** | **2345.0** | **+12.39%** |

**以上为带宽外推，不是收益承诺，须实测锁定。**

**实现路径（保持 KB=4，提 blocks 到 3）**：需 shared ≤33792（现 44288，降 10496）。
- `MMA_LD` padding 8 不能动（ldmatrix 每行 16B=4 banks，LD=72 恰好不重叠）
- **S 不能降**（会直接削 MLP，本归因已证）
- `bsh_s` 改单缓冲省 8192，仍超 2304 B
- `MMA_ROWS` 64→32 可到 31360，但运行期非法访问（与 warp/ldmatrix 行布局、work 编码强耦合）

**⇒ 必须源码级适配，属重写施工。方向明确：在不削弱每-warp 预取深度的前提下压缩 shared 占用。**

**新增可试方向**：既然 KB↑ 提 MLP，`KB=8`（shared 85248 ⇒ blocks 1）是「高 MLP/低并发」的另一端，
需实测权衡；此前仅按 blocks 数排除过它，**未从 MLP 角度评估**。

## §6 新增方法论

- **§7.32 找中介变量，别停在相关**：判「X 是主因」须测出 X 与结果之间的**中介量**，
  并证明结果与中介量一一对应。本轮中介量是**有效 DRAM 带宽**，`T = 字节/带宽` 五对照误差 ≤0.2%。
- **§7.33 两点拟合不得立论**：两点拟合任意两参数模型必然完美。
  本轮 `T=A/warp+B` 两点得 B≈8.86 并据此推断「DRAM 基座」，**第三点直接否证**。凡分解模型须 ≥3 点。
- **§7.34 用未使用的 shared 做纯净 occupancy 探针**：当 kernel 走静态 shared 分支
  （`DYN=false`）时，`extern __shared__` 未被访问，可用启动期动态 shared 申请量单独压 occupancy，
  **指令与输出位全不变**，得到位一致的因果探针。优于任何改模板参数的 A/B。
