## §0 主因判决：已确定，无第二可能性

**内核跑不满的主因 = 2.9bpw trellis 反量化产生的标量指令占据了发射带宽，而寄存器/shared 容量使得「提并发」与「保权重复用」不可兼得，四个可调旋钮互为配平、零和。**

不是任何单一硬件资源饱和，不是 spill，不是 bank 冲突，不是同步栅栏，不是时钟。

**三条独立证据互证：**

1. **指令构成**：真正的张量数学 HMMA 只有 **98,242,560 条 = 总指令的 5.59%**；ALU 有 **717,729,264 条 = 40.85%**，**ALU : HMMA = 7.31 : 1**。每做 1 条张量数学要付 7.31 条标量指令。
2. **恒等式**：`T = N_inst × L_dep / (SM × warp槽 × warp% × CLK)`，两种独立形式交叉校验误差 **1.0% / 3.1%**。时间只由三个因子决定，全部已实测。
3. **反证**：所有试图提并发的改动都让 `N_inst` 增幅超过并发增幅（见 §4），无一例外。

**硬天花板**：`u_dram = 0.6082`，DRAM 流量 1.861 GiB ⇒ **gate/up 的 DRAM 硬下界 8.1181 ms**，相对当前 12.7547 ms **最多快 1.571×（−36.4%）**。这是物理下界，任何软件改动都突破不了。

## §1 时间的三因子恒等式

```
T = N_inst × L_dep / (48 SM × 48 warp槽 × warp% × CLK)
L_dep = (warp% × 48 warp槽) / (4 scheduler × issue%)
```

`L_dep` 的物理意义：**同一 warp 内相邻两条指令的平均间隔**（依赖延迟）。

| 臂 | N_inst | warp% | issue% | L_dep(cyc) | 预测 T | 实测 T | 误差 |
|---|---:|---:|---:|---:|---:|---:|---:|
| base（生产同款 S3/KB4/MB1） | 1,756,808,496 | 33.20 | 30.47 | **13.0752** | 13.2115 | 13.3443 | −1.00% |
| new（S2/KB2/MB3） | 3,317,512,896 | 49.78 | 42.46 | **14.0688** | 17.9033 | 17.3703 | +3.07% |

等价形式 `N_inst = 48 × 4 × cycles × issue%` 独立校验：+1.01% / −2.98%。**恒等式成立。**

**要变快只有三条路：减 N_inst、降 L_dep、提 warp%。** 三者的可调手段与代价见 §4。

## §2 E-SIM-02 判决实验：把仿真的 S3 方案落地实测

仿真 S3 预测「KB=2 + 3 blocks 无 spill ⇒ −18.12%」。为兑现它，先做编译期预筛找可达配置。

**编译期预筛**（`cuobjdump -res-usage`，HI=10 生产同款 range）：

| 配置 | REG | spill | shared | blocks = min(reg限, sh限) |
|---|---:|---:|---:|---|
| S=3 KB=4 MB=1（生产） | 124 | 0 | 45312 | min(2,2) = **2** |
| S=2 KB=4 MB=1 | 106 | 0 | 36096 | min(2,2) = 2 |
| S=2 KB=2 MB=1 | 97 | 0 | 19712 | min(2,5) = 2 |
| S=2 KB=4 MB=3 | 80 | 32B | 36096 | min(3,2) = 2 ← 白付 spill |
| **S=2 KB=2 MB=3** | **80** | **8B** | **19712** | min(3,5) = **3** ← 唯一可达且 spill 最小 |

**`MMA_LD` 的 padding 8 不能动**：ldmatrix 每行取 16B = 4 banks，`LD=72` 让 row r 占 bank 4r..4r+3 **恰好不重叠**；减到 66 会让相邻行重叠。源码注释「ldmatrix rows fall in distinct banks」是有硬理由的。

**同场 A/B 实测**（12 轮 A/B 交替，臂间 0.25s 冷却，对照臂同场重测）：

```
base(S3,KB4,MB1) 12.5900 ms    new(S2,KB2,MB3) 16.2821 ms    delta +29.33%
位一致 torch.equal = True   maxdiff = 0.000e+00
配对差 6/6 同向：[28.21, 31.75, 29.31, 27.78, 29.27, 29.49]
极差 base 0.21% / new 3.00%
```

**仿真预测 −18.12%，实测 +29.33%。方案否决。**

## §4 四旋钮零和：为什么参数调优已到尽头

`KB`（k-tile 步长）与 `S`（MMA_STAGES，行流水深度）同时是**权重复用因子**：减小任何一个，同一份解码后的权重被更少的数学工作复用 ⇒ **反量化指令增加**。而它们又是**唯一能降 shared 的旋钮**；`MINB` 是**唯一能降 REG 的旋钮**，代价是编译器重调度增指令。

| 改动 | warp% | N_inst | 净时间 | 判决 |
|---|---:|---:|---:|---|
| KB 4→2（纯，MB=1） | +0.03% | **+35.08%** | **+20.55%** | 亏 |
| MINB 1→3（KB=2 固定） | **+49.70%** | +42.03% | −6.18% | 微赚 |
| MINB 1→3（KB=4，shared 钉 2） | −0.09% | +34.53% | +4.95% | 亏（warp 没涨） |
| **S 3→2 + KB=2 + MINB=3** | **+49.94%** | **+88.84%** | **+29.33%** | 大亏 |
| down 的 red padding=4 | 不变 | 不变 | −1.08% | 微赚（bank 冲突 6.02→2.04×） |

**规律：并发每涨 ~50%，指令必涨 42%~89%。指令弹性 ≈ 0.59，并发弹性 ≈ 1.0，但两者被同一组旋钮绑定，无法独立优化。**

**KB=4 下 3 blocks 在当前结构不可达**：shared 44288 需降到 ≤33792（降 10496），而 padding 不能动（ldmatrix bank）、S 不能降（指令暴增）、`bsh_s` 改单 buffer 只省 8192 仍超 2304。**仿真 S4/S5 的 −31%/−36% 在参数层面无实现路径。**

## §5 仿真器：已建成、已标定、已知失效边界

`tools/sim-kernel.py`，三子命令 `explain | calibrate | scan`，纯本地无 GPU。

三层模型：发射界 + 各资源界（shared / DRAM / tensor）+ 依赖延迟 `L = L0 + Σ s_k·u_k` 迭代求解。
标定：`s_shared = 2.2717`（down PAD 实验）、`L0 = L_base − s_sh·u_shared − s_dr·u_dram`（避免重复计）。
自校验：S0 精确复现 +0.00%，S1/S2 误差约 7%。

**已知失效边界（E-SIM-02 暴露）**：

1. **模型把 `L0` 当常数，但 `S` 减小会削弱流水线延迟隐藏** ⇒ 实测 L_dep 13.075→14.069（+7.6%），模型未计。
2. **模型不能预测「改动会产生多少指令」**。S3 假设「无 spill 即无指令代价」，实测即使 spill 仅 8B，指令仍 +88.84%（uniform/adu/cbu 重调度）。**这是模型最大的结构性缺陷。**
3. `s_dram` 未标定取 0（保守）；`s_shared` 跨内核借用 down 的标定值；down 的 `u_dram` 未测。

**⇒ 仿真器只能用于「给定 N_inst / warp / L 三因子后算时间」与「算资源硬下界」，不能用于「预测某源码改动的收益」。收益必须实测。**

**扫描结果**（`raw/scan.json`，S3~S9 均为外推，**不得当收益承诺**）：

| 方案 | T(ms) | vs生产 | u_dram | 绑定界 | 落地判决 |
|---|---:|---:|---:|---|---|
| S0 生产基线 | 12.7547 | +0.00% | 0.636 | issue | 精确复现 |
| S3 KB=2+3blocks 无spill | 10.4429 | −18.12% | 0.777 | issue | **实测 +29.33%，否决** |
| S4 KB=4+3blocks 无spill | 8.7806 | −31.16% | 0.925 | issue | **参数层无实现路径** |
| S5/S6/S7 | 8.1181 | −36.35% | **1.000** | **dram** | 撞物理下界 |
| S8 shared 流量归零 | 11.8936 | −6.75% | 0.683 | issue | 上界，非承诺 |
| **S9 DRAM 字节减半** | 12.7547 | **+0.00%** | 0.318 | issue | **单独减字节当前无收益** |

**S8 与 S9 合起来就是「多点配平」的定量证据**：单独减 shared 只值 −6.75%，单独减 DRAM 字节值 **0%**，因为当前绑定界是 issue 不是 dram。**必须先把 issue 界压下去，减字节才开始兑现。**

## §6 改进目标反解（唯一出路）

既然旋钮零和，出路只有一条：**降低每字节权重的解码指令数本身**，即改反量化算法，而不是调分块参数。

以 DRAM 硬下界 8.1181 ms 为目标（warp/L 不变）：

- 需 `N_inst ≤ 1,118,171,894`，即 **削 638,636,602 条（−36.4%）**
- 若全部从 ALU 削：ALU 需从 717,729,264 降 **89.0%**（近乎消除，不现实）
- **若 ALU 减半**：N −20.4% ⇒ T ≈ **10.1493 ms**
  全局折算：gate/up 1466.505 ms 省 **299.6 ms** ⇒ span 4858.2 ms ⇒ **2215.2 tok/s（+6.16%）**

**ALU 减半是现实的第一目标，对应全局 +6.2%。** 具体算法设计见 `docs/performance/04-算法改进策略.md`。

## §8 本轮新增方法论

- **§7.23 指令分类差分**：判定「指令为何增加」必须按管线拆开（alu/fma/lsu/cbu/uniform/adu/tensor），并单独核 spill 的 `local_ld/st` 指令数。**只看 spill 字节或 REG 数会把编译器重调度误判成 spill。**
- **§7.24 干预干净性判据**：改分块/并发参数时，**HMMA 条数、ldmatrix 条数、global 读条数必须完全不变**，否则数学工作量或访存量也变了，A/B 不干净。
- **§7.25 仿真器的能力边界**：模型可算「三因子 → 时间」与「资源硬下界」，**不可预测「源码改动 → 指令数」**。凡涉及编译器重调度（REG 压力、循环结构）的收益，一律实测。
