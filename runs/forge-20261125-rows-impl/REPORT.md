# E-ROWS-01/02：MMA_ROWS 源码级适配成功，但收益否证 —— 并推翻「MLP 不足是主因」

**日期**：2026-11-25　**生产全程未停服**，`start.sh` 未改动，所有改动仅在离线容器 `exl3-rows`。

## §0 三句话结论

1. **施工成功**：`MMA_ROWS` 64→32 的源码级适配完成，非法访问彻底修好，**位一致 maxdiff=0**，
   3 blocks 达成（warp 33.20%→49.78%）。R=64 回归臂与生产**逐项相同**（REG 124 / spill 0 / shared 45312 / blocks 2）。
2. **收益否证**：时间 **+1.21%（ncu）/ +2.92%（墙钟，配对不同向）**，有效带宽 **150.13→148.44 GB/s（−1.13%）**。
   我上一轮建的 MLP 饱和模型预测 175.20，**误差 +18.03%，模型被否证**。
3. **更重要的自查**：E-OCC-02/03 宣称的「机制链闭合」论证**有根本缺陷**——
   `T = DRAM字节/有效带宽` 是**恒等式**（带宽的定义就是字节/时间），五对照误差 ≤0.2% 只证明测量自洽，
   **不构成因果证据**。真正的因果检验是双向干预，而增并发方向**断裂**。
   **正确结论：内核是已配平的流水线，不存在可单点修复的主因。**

## §1 施工：非法访问的真因与修法

### 真因（四处硬编码，全部定位）
原源码把「64 行 = 4 row-group × 16 行」「256 线程 = 64 行 × 4 线程」写死：

| # | 位置 | 原式 | R=32 时的后果 |
|---|---|---|---|
| 1 | `mma_slice` cp.async 行分配 | `crow = threadIdx.x >> 2` | crow∈0..63，`rows_sh[32..63]` 越界 |
| 2 | `mma_slice` ldmatrix 行 | `lrow = rg*16 + …`，`rg = warp&3` | lrow 可达 63，`As[..][63]` 越界 |
| 3 | kernel epilogue 行 | `r0/r1 = rows_sh[rg*16+g8(+8)]` | 同上 |
| 4 | cp.async chunk 分工 | 每行 4 线程 × `CPR=KB/2` | R32 需每行 8 线程，chunk 索引与 src 偏移全错 |

第五处是 work 编码，但 `m2_work(counts, uids, ucount, work, rows)` **本就带 rows 参数**，
probe 传 32 即可，无需改源码。（上一轮 R32 失败正是这五处未同时适配。）

### 修法：全部由 MMA_ROWS 派生，R=64 时逐字等价
```
MMA_RG  = MMA_ROWS/16          row-group 数（原 4）
MMA_CG  = 8/MMA_RG             col-group 数（原 2）
MMA_NJ  = (MMA_COLS/16)/MMA_CG 每 warp 的 n16 tile 数（原 2）
MMA_TPR = 256/MMA_ROWS         每 staged row 的线程数（原 4）
CPR     = KB*16/(8*MMA_TPR)    每线程每步 chunk 数（原 KB/2）
```
`rg = warp%MMA_RG`、`cg = warp/MMA_RG`，累加器 `[4][4]`→`[MMA_NJ*2][4]`。
R=32 ⇒ RG=2 CG=4 NJ=1 TPR=8 CPR=1：8 warp = 2 row-group × 4 col-group，每 warp 16 行 × 16 列。
block 输出 32×64（原 64×64 的一半）⇒ work 对数 602→820，**总工作量不变**。

`tools/patch-mma-rows.py`，16 处替换全部 `count==1` 断言，幂等 MARK=`TF_MMA_ROWS_APPLIED`。

### 三道闸全过
| 闸 | 判据 | 结果 |
|---|---|---|
| 回归 | ref(原件) vs r64 位一致 | **True，maxdiff=0** |
| 回归加强 | r64 资源画像 vs 生产 | **REG 124 / spill 0 / shared 45312 / blocks 2，逐项相同** |
| 适配 | ref vs r32 位一致 | **True，maxdiff=0** |

编译期预筛（**mangled 名精确匹配** `grouped_mma_kernelILi2ELi2ELi10ELb1ELi4E`）：

| 臂 | REG | spill | shared | blocks |
|---|---:|---:|---:|---:|
| r64 | 124 | 0 | 45312 | 2 |
| r32 | 80 | **0** | 31360 | **3** |

## §3 两个假设的否证

### §3.1 否证我自己的 MLP 饱和模型
上一轮建 `B(w,k) = 246.2·wk/(wk+38.9)`，5 点标定最大误差 2.92%，据此预测 R32 ⇒ 175.20 GB/s。
**实测 148.44，误差 +18.03%** ⇒ 模型在「增并发」方向失效。

失效原因：模型用 `w·k`（warp 数 × KB）作 MLP 代理，但**新增的 warp 读的是同一批权重**
（L2 命中上升、DRAM 请求数不变），不产生新的在飞 DRAM 请求 ⇒ 代理量与真实 MLP 脱钩。

### §3.2 否证「粒度墙」假设
怀疑 ~150 GB/s 是访问粒度造成的。采 A/B 两侧粒度计数器：

| 通路 | sectors/request | 等效字节 |
|---|---:|---:|
| L1 权重侧 global ld | 8.446 → 6.742 | 270.3 → 215.7 B |
| L2 全部读 | 1.673 → 2.226 | 53.5 → 71.2 B |
| **L2 miss → DRAM** | **3.999 → 3.999** | **128.0 B（满 burst）** |

**DRAM 侧粒度是满的，粒度墙假设否证。**

**决定性读数**：DRAM miss **请求数** 15,609,595 → 15,621,579（**+0.08%**）。
warp +50% 没有带来任何新的在飞 DRAM 请求。

> 附注：`l1tex__*_ldgsts_cache_access.*`（cp.async 通路）在 GB10 上读数恒 0，
> A 侧流量并入普通 global ld 计数，不能据此认为 cp.async 未生效。

## §4 根本自查：恒等式自洽 ≠ 因果闭合

E-OCC-02/03 用「`T = DRAM字节/有效带宽`，五对照误差全 ≤0.2%」宣称机制链闭合。**这个论证是错的。**

因为**有效带宽的定义就是 `字节 / 时间`**，所以 `T = 字节 / (字节/T)` 恒成立。
误差 ≤0.2% 只反映两次测量的自洽性，**与因果无关**。
这正是手册 §7.29「恒等式不是因果模型」已经立下的规矩，我在新形式下又犯了一次。

本轮第六个对照误差 +0.07%，同样只是恒等式自洽，**不再作为因果证据**。

**真正的因果检验是双向干预**，结果不对称：

| 方向 | 干预 | warp 变化 | 时间变化 | 弹性 |
|---|---|---:|---:|---:|
| **减并发** | dyn pad 压 blocks 2→1 | −50.08% | **+30.00%** | 0.60 |
| **增并发** | R32 腾 shared 得 3 blocks | **+49.94%** | **+1.21%** | **−0.024** |

⇒ 生产工作点位于「**减并发有害、增并发无益**」的平台上。
「并发不足是主因」只在减方向成立，**不能外推为「增并发可获收益」**。

## §5 正确结论：结构性配平，无单点主因

**这与 E-SELF-10（同日早先）的定案一致**，`docs/CURRENT-BASELINE.md` 早已写明：
> 「DRAM 62% / Tensor 46% / SM 50% / L2 25% 同时不饱和是**配平的必然表现**，
> 内存侧与计算侧**互为止点**」

也与用户「**多点配平**」的判断一致。本轮把它从「推断」升级为**全杠杆双向实测**：

| 杠杆 | 干预方式 | 机制量变化 | 时间变化 | 弹性 |
|---|---|---:|---:|---:|
| warp 并发 ↓ | 未使用 shared 做纯净探针 | warp −50.08% | +30.00% | 0.60 |
| **warp 并发 ↑** | **R32 源码适配腾 shared** | **warp +49.94%** | **+1.21%** | **−0.024** |
| 指令数 ↓ | cb_pair 4→2（纯净） | 指令 −17.41% | −1.00% | 0.058 |
| **指令数 ↑** | **R32 block 数翻倍** | **指令 +55.12%** | **+1.21%** | **0.022** |
| shared bank | down PAD=4 | wavefront −24.30% | −1.08% | 0.044 |
| tensor 管线 | 反向夹逼（E-SELF-11） | — | ≲2.5% | — |
| 集合通信 | 协议/env 全族 | 达屋顶 92.2% | — | 仅 1.085× 余量 |

**资源同时贴顶**（2 blocks 预算）：**REG 124/128 = 96.9%**、**shared 45312/50688 = 89.4%**。
任何加深预取或增大 tile 的改动都会掉 occupancy —— 这本身就是配平的物理表现。

### 撤回「61.1% 屋顶、1.633× 余量」
`docs/CURRENT-BASELINE.md:404` 早有教训：
> 「屋顶内核的 429 GB/s **不可迁移**——它是自由布局顺序读，不受 fragment 布局约束」

246.2 GB/s 是自由布局纯读标定，**对本内核（fragment 布局 + shared 往返 + 配平流水）不可直接作分母**。
参照：decode 内核在同硬件达 82.8% 屋顶，但那是不同访问模式。
⇒ **「150.49/246.2 = 61.1%，还有 1.633×」这个表述撤回**。真实可达上限须用**同结构**屋顶重新标定。

### 「100% 归因」的正确表述
能 100% 确定的是：**不存在可单点修复的主因，瓶颈是结构性配平**。
这有完整的双向干预 + 弹性证据链。
而「主因 = MLP 不足」**已被本轮否证**，不再成立。

两者是不同的命题：前者是「已穷尽单点杠杆」的结论，后者是「找到一个可修的单点」的结论。
**本轮确定的是前者。**

## §6 剩余未测方向（诚实标注）

- **权重侧 `load_words` 预取深度**（当前 1 步：`st+2` 加载、`st+1` 消费）是与 warp 数**不同的杠杆**，
  本轮未测。但 REG 只剩 4 个余量（124/128），加深必掉 occupancy ⇒ 受硬约束。
- **同结构屋顶标定**：用与本内核相同 fragment 布局的纯搬运内核标定可达上限，
  才能给出真实余量。这是替代 246.2 的正确分母。
- 注意力/HC 17.57%（906.308 ms）**仍从未归因**，是全局最大空白。

**下一步真正方向**：改变「每搬运字节的算术量」或数据布局（**结构级重写**），而非调参数。
所有参数级杠杆已实测封顶。

## §8 本轮新增方法论（已入手册）

- **§7.35 恒等式自洽不是因果闭合**：若「机制量」由结果量定义（带宽=字节/时间），
  两者一致是必然，不构成因果证据。必须做**双向干预**。
- **§7.36 单向弹性不得外推**：减方向弹性 0.60 与增方向 −0.024 可以并存（平台/局部最优）。
  称「X 不足是主因」前必须证明**增 X 有收益**。
- **§7.37 屋顶分母的可迁移性**：自由布局纯读屋顶不可作受布局约束内核的分母，须同结构标定。
- **§7.38 预筛与 ncu 一样必须验内核身份**：cuobjdump 是 **mangled 名**，
  且不得取「shared 最大者」——会抓到别的模板变体，得出与实测矛盾的 blocks 数。
